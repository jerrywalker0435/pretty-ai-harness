# Plan 中的测试代码设计

本文件只约束 `plan.md` 中展示的核心测试代码。Plan 不规定 TDD 流程，不运行测试、不写验证命令、不设覆盖率目标；Execution 根据 PRD、Design、Plan 和届时仓库状态完成测试实现与验证。

## 核心测试代码必须表达

- 使用 public 行为入口，不为测试暴露 private 方法。
- 使用真实领域输入、规则和对象；只替换持久化、网络、时间、随机等边界协作者。
- 一个测试聚焦一个可观察结果，名称使用领域语言。
- 断言业务结果、状态变化、异常合同或完整边界请求；调用次数/顺序不能成为主要成功证据。
- 展示会改变结果的正常、边界和失败路径；幂等、并发或兼容分支只在真实适用时出现。
- 每个新增信任边界至少展示一个非法输入或响应，固定其明确异常/失败映射；长度、格式和可空性边界按已批准 Schema 或外部协议取值。
- fixture 和期望值独立于拟议实现，不能复制同一计算逻辑来证明自己。
- 不使用 Spring 上下文、真实数据库、Testcontainers 或外部基础设施掩盖错误的单元边界。

## 与生产代码的关系

测试和生产调用必须穿过同一个 Interface/Seam。测试若必须穿透私有实现、反射访问或扩大可见性，说明 Module 形状需要重设计。

行为保持型重构展示能固定现有外部结果的测试代码；新行为展示其目标结果和失败合同。Plan 不声称测试已经失败或通过，也不要求 Execution 按 Plan 中的代码逐字实现。

## 测试栈

只使用仓库已存在且与 Java/Spring 版本兼容的 JUnit、Mockito、AssertJ 或其他测试库。仓库没有现成测试栈时，Plan 不擅自新增依赖；把依赖选择返回 Design 或交给 Execution 依据项目约束处理。

声明/结构变更型的配置、资源、文档、移动和确定性改名任务不强制附带测试代码；若它们实际改变运行时逻辑，则应按逻辑实现型 TASK 处理。

SQL、DDL、索引和迁移脚本不写“SQL 单元测试”。这类 TASK 使用独立的 `数据库验证`：声明验证类型和目标引擎，以非破坏性 SQL 固定解析结果、迁移后置条件、查询结果或执行计划。只有 Java 调用方的可观察行为需要放入 `测试`。
