# Java 代码提案降级参考

仅当相关 Java 质量 Skill 未安装，且代码提案命中对应风险时读取本文件。它是降级清单，不在每次 Plan 中强制加载，也不替代 `references/quality-principles.md`。

## 创建、封装和类型

- 构造器简单且参数不混淆时直接使用；只有复杂可选参数和共同不变量才考虑 Builder。
- 依赖由构造器显式传入，不藏在静态单例、Service Locator 或业务方法内部 `new` 中。
- 对象能不可变就不可变；可变输入/输出只在确有泄漏风险时防御性复制。
- 组合优先于继承；继承必须保持前置条件、结果、异常和副作用可替换。
- 身份、金额、单位、状态和约束在跨边界或易混淆时使用领域类型；局部普通值不强制包装。
- 集合不返回 `null`；`Optional` 只表达明确的返回缺失，不作为所有字段/参数的通用包装。
- 精确金额和舍入使用适当精度类型，不用 `double` 代替。

## 方法、异常和资源

- 方法签名表达必填、可选和失败合同；不以通用 `Command/Param/Result` 隐藏模糊语义。
- 在真实信任边界校验一次，内部依赖已建立的契约；不要层层 null/blank 防御。
- 不用异常控制普通业务分支，不吞异常、不丢失 cause、不把故障转换成空成功。
- 资源由创建/拥有它的 Module 关闭；使用 try-with-resources 或等价生命周期保证。
- 幂等、事务、重试和部分副作用必须属于明确 Interface 或实现限制。
- Stream/Lambda 只在提高意图表达时使用；不要隐藏 I/O、事务、共享可变状态或顺序依赖。

## 选择原则

每条建议必须对应真实代码风险。不要为了展示 Effective Java 而强行引入静态工厂、Builder、值对象、Optional 或设计模式；更好的设计应减少调用方知识、集中规则并让失败更明确。
