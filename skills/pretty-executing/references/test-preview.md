# Execution Preview 中的测试提案设计

本文件只约束 `execution-preview.md` 中展示的核心测试提案。Preview 不规定 TDD 流程，不运行测试、不写执行结果；Apply 根据 PRD、Design、Preview（如用户提供）和届时仓库状态完成测试实现与验证。

## 核心测试代码必须表达

- 使用 public 行为入口，不为测试暴露 private 方法。
- 使用真实领域输入、规则和对象；只替换持久化、网络、时间、随机等边界协作者。
- 一个测试聚焦一个可观察结果，名称使用领域语言。
- 断言业务结果、状态变化、异常合同或完整边界请求；调用次数/顺序不能成为主要成功证据。
- 展示会改变结果的正常、边界和失败路径；幂等、并发或兼容分支只在真实适用时出现。
- 每个新增信任边界至少展示一个非法输入或响应，固定其明确异常/失败映射；长度、格式和可空性边界按已批准 Schema 或外部协议取值。
- fixture 和期望值独立于拟议实现，不能复制同一计算逻辑来证明自己。
- 不使用 Spring 上下文、真实数据库、Testcontainers 或外部基础设施掩盖错误的单元边界。

## 与生产代码的关系

测试和生产调用必须穿过 Design 已批准的同一个公共验证入口。测试若必须穿透私有实现、反射访问或扩大可见性，说明模块职责需要重设计。

行为保持型重构展示能固定现有外部结果的测试提案；新行为展示其目标结果和失败合同。Preview 不声称测试已经失败或通过，也不要求 Apply 按 Preview 中的代码逐字实现。

## 测试栈

只使用仓库已存在且与 Java/Spring 版本兼容的 JUnit、Mockito、AssertJ 或其他测试库。仓库没有现成测试栈时，Preview 不擅自新增依赖；把依赖选择返回 Design 或交给 Apply 依据项目约束处理。

声明/结构变更型的资源、移动和确定性改名任务不强制附带测试代码；若它们实际改变运行时逻辑，则应按逻辑实现型 TASK 处理。配置数据不属于 Preview，项目治理文档不得由 Agent 自行纳入范围。

表、字段、索引等 DDL 只能展示拟交付文件，不写测试、执行命令或数据库验证。Java 与 DDL 混合 TASK 只为 Java 调用方的可观察行为展示测试，不用 Java 测试、SQL 文本断言或验证命令证明 DDL。配置数据 DML 不属于 Preview。
