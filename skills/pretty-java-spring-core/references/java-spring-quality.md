# Java/Spring 专项质量检查

只判断真实变更命中的 Java/Spring 风险，不强制固定架构。

## 职责与依赖

- Controller 只负责协议转换、输入校验和响应映射；业务规则有明确归属。
- 使用构造器注入；依赖指向稳定业务边界，避免循环依赖和隐藏实例化。
- DTO、领域对象和持久化对象只按真实边界分离，不做无收益逐层复制。
- 没有当前第二个使用者时，不引入接口、工厂、策略或模式开关。

## Java/Spring 风险

- 事务边界覆盖完整业务用例；明确回滚、并发、锁、幂等与重试语义。
- 在 HTTP、消息和反序列化等信任边界执行 Bean Validation 或等价校验。
- Repository 查询明确数据规模、分页、批量操作、N+1 和索引影响。
- 异常保留原因与上下文，并稳定映射到外部错误合同。
- null、资源关闭、线程安全、性能和 API 兼容风险按实际差异检查。
- 日志不泄露凭证、个人信息或完整敏感载荷；关键失败保留必要上下文。

## 组合代码质量

- 在 Plan 编码前按最终生产 symbol 检查累计职责和依赖，不按 TASK 局部堆叠。
- 一个业务规则只有一个权威实现位置；相同知识不得分散到 Service、Policy、Adapter 或 fixture。
- 同一类跨 TASK 修改、同时包含业务编排与基础设施 DTO、或服务多个独立 actor 时，先重新划分职责。
- 业务层依赖由业务侧定义的窄端口；Adapter/Infra 实现端口，不泄漏远端 DTO、Mapper 或框架类型。
- 不为没有当前第二个使用者的变化轴引入接口、工厂、策略、模式开关或通用命令。
