# Java/Spring 专项质量检查

只检查与真实变更相关的风险，不强制固定架构。

## Design 与 Plan

- Controller 只负责协议转换、输入校验和响应映射；业务规则有明确归属。
- 使用构造器注入；依赖指向稳定业务边界，避免循环依赖和隐藏实例化。
- 事务边界覆盖完整业务用例；明确回滚、并发、锁、幂等与重试语义。
- DTO、领域对象和持久化对象只按真实边界分离，不做无收益逐层复制。
- 在 HTTP、消息和反序列化等信任边界执行 Bean Validation 或等价校验。
- 明确 Repository 查询规模、分页、批量操作、N+1 和索引影响。
- 异常保留原因与上下文，并稳定映射到外部错误合同。
- 日志不泄露凭证、个人信息或完整敏感载荷；关键失败保留必要上下文。
- 选择满足当前需求的最简单结构；没有第二个现实实现时不引入接口、工厂或策略。

## UT-only

- 只新增或扩展不启动 Spring、不访问真实/嵌入式基础设施的 UT。
- 使用真实被测规则、领域对象和纯内存协作者。
- Repository、Gateway、远程客户端、时钟、随机性及其他边界接口可以 mock/fake/stub。
- 断言业务结果、状态变化或完整边界请求，不以 Mockito 次数或顺序为主要成功标准。
- 禁止新增或扩展 Spring slice、集成、契约、端到端、Testcontainers 或嵌入式基础设施测试。
- SQL、配置、文档和机械修改使用静态解析、编译、搜索不变量或确定性脚本，不制造 UT。

## 覆盖率

- 优先继承仓库明确政策；无政策时，可由 UT 覆盖的新增或实质修改 Java 行为默认行 90%、分支 80%。
- 修改既有行为必须有针对性 UT；工具不能统计修改行时不得虚构百分比。
- SQL、配置、文档、生成物、机械修改和未触碰历史代码不纳入治理。
- 金额、权限、状态、幂等和事务一致性按真实行为矩阵覆盖关键路径。
- 覆盖率不能替代有效断言、边界和错误路径，也不能授权非 UT 或无价值测试。
